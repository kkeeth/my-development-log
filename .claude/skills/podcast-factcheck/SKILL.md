# 台本のファクトチェック

**この工程は「全部を検証する」ものではない．** 間違っていたときに一番痛い主張を
上位 5 件だけ潰して終わる．網羅性より打ち切りを優先する．

## 手順

### 1. 対象台本を特定する

引数でファイルパスが渡されていればそれを使う．
無ければ `src/PODCASTS/WEB小噺/Season5/` の中で配信ステータスが「未配信」のもののうち，
**更新日時が最新のものを黙って選ぶ**．該当が 0 件のときだけユーザーに聞く．

### 2. 検証を 1 本の subagent に投げる

`podcast-fact-checker` エージェントを **1 本だけ** spawn する．並列化しない
（同じ台本を 2 本に読ませると fetch も出力も倍になり，得るものは重複だけ）．

渡すもの：台本の全文パスと，「検証は最大 5 件・`WebFetch` は最大 8 回で打ち切り」の指示．

自分では `WebFetch` / `WebSearch` を追加で叩かない．subagent の結果をそのまま使う．

### 3. 台本に反映する

`⚠️ 要修正` の修正案を **確認を取らずに `Edit` で適用する**．
`❓ 裏取り不能` / `🔀 諸説あり` も，言い切りを弱める修正案が出ていれば適用する．

- 適用してよいのは subagent が根拠 URL つきで出した修正だけ．根拠が無いものは触らない
- 検証で新たに使った URL を，台本末尾の `📎` リストに追加する
- `## 📚 参考情報` セクションに検証済みファクトを箇条書きで残す
  （`SHOW_RULES.md` の台本フォーマット参照）

### 4. ユーザーに報告する

適用後に，**20 行以内**で結果を報告する．

```markdown
## ファクトチェック結果：{台本タイトル}

**総評**：{配信可 ／ 修正後に配信可 ／ 要再構成}
検証 N 件（要修正 N／裏取り不能 N／諸説あり N／確認済み N）｜未検証 N 件

### 台本に当てた修正
- {該当箇所}：{修正前 → 修正後}（📎 URL）

### 判断が要るもの
- {諸説ありで自動修正しなかったもの。無ければこの節ごと省く}
```

ユーザーが差し戻したい修正は `git diff` で見られるので，
**事前に 1 件ずつ承認を求めない．**

## 注意

- 存命／逝去，事件・事故，係争中の話題は最優先で検証枠に入れる．誤りが実害になる
- 予算内で終わらなかった主張は「未検証」として正直に残す．追加調査に入らない
- 文体や構成の指摘はここではしない．それは `podcast-review` の担当
