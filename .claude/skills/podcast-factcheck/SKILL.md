# 台本のファクトチェック

## 手順

### 1. 対象台本を特定する

引数でファイルパスが渡されていればそれを使う．
無ければ `src/PODCASTS/WEB小噺/Season5/` の中で**配信ステータスが「未配信」のもの**を一覧し，
どれを検証するかユーザーに確認する．

### 2. 検証を分担して並列実行する

`podcast-fact-checker` エージェントを **2 本並列で spawn** する．分担は：

- **A：数値・固有名詞・日付**（年号，金額，年齢，バージョン，人名・社名の綴り）
- **B：因果関係・断定表現・引用**（「〜が理由で」「世界初」「唯一」，発言の引用，存命／逝去）

両方に台本の全文パス（またはインライン全文）を渡す．
分担しても**台本全体を読ませる**こと．文脈なしで数値だけ見ても判定できない．

### 3. 結果を統合する

2 本の結果をマージし，重複を除いて**判定区分ごと**にまとめ直す．
両者の判定が食い違う主張があれば，自分で `WebFetch` して裁定する．

### 4. ユーザーに提示する

```markdown
## ファクトチェック結果：{台本タイトル}

**総評**：{配信可 ／ 修正後に配信可 ／ 要再構成}
**要修正 N 件／裏取り不能 N 件／諸説あり N 件／確認済み N 件**

（以下、要修正から順に、該当箇所の引用・実際・根拠 URL・差し替え文）
```

### 5. 反映する

ユーザーが承認した修正だけを台本に `Edit` で適用する．**勝手に全部直さない**．
検証で新たに使った URL は，台本末尾の `📎` リストに追加する．

修正を適用したら，`## 📚 参考情報` セクションに検証済みファクトを箇条書きで残す
（`SHOW_RULES.md` の台本フォーマット参照）．

## 注意

- 数値は 1 つ残らず検証対象．「だいたい合ってそう」で飛ばさない
- 存命／逝去，事件・事故，係争中の話題は特に厳密に．誤りが実害になる
- 文体や構成の指摘はここではしない．それは `podcast-review` の担当
