# 台本の構成レビュー（マーケター視点）

## 手順

### 1. 対象台本を特定する

引数でファイルパスが渡されていればそれを使う．
無ければ `src/PODCASTS/WEB小噺/Season5/` の未配信ファイルを一覧して確認する．

### 2. レビューを実行する

`podcast-marketer` エージェントを spawn する．渡すもの：

- 台本のファイルパス
- `## 📣 配信メタ` セクションがあれば，タイトル案・概要欄も評価対象に含めるよう指示
- 尺の希望があれば伝える（デフォルトは `SHOW_RULES.md` の目標 28〜30 分）

### 3. 自分でも本編の文字数を数える

エージェントの尺見積もりを鵜呑みにせず，`## 台本` 配下の本文文字数を数える．

```bash
# 本題セクションの文字数（目安：300〜350 字/分）
# 📎 の行は読み上げないので必ず除外する．含めると尺を過大に見積もる
awk '/^### 本題/,/^### エンディング/' <file> | grep -v '📎' | tr -d '[:space:]' | wc -m
```

### 4. 結果を提示する

エージェントの採点表と改善提案をそのまま見せたうえで，
**「今回この台本で最も効く直しは何か」を自分の言葉で 1 つに絞って**述べる．
提案が 5 件並んでいても，実際にやるべきは大抵 1〜2 件である．

### 5. 反映する

ユーザーが採用した提案だけを `Edit` で台本に適用する．
本文を書き換えたら，事実関係が変わっていないか確認する．変わっていれば `podcast-factcheck` の再実行を勧める．

## 注意

- 番組の世界観（ゆるさ，蘊蓄，雨宿りのメタファ）を壊す提案は採用しない．
  数字のために番組らしさを捨てると，レビューが番組を殺す
- 「削る」提案は具体的な範囲を指定させる．「冗長です」だけでは動けない
- 事実の正誤は扱わない．それは `podcast-factcheck` の担当
