# ポッドキャスト制作パイプライン

「雨宿りと WEB の小噺」1 エピソードを通しで作る．
各工程は個別の skill としても呼べる．**この skill は順序と引き継ぎだけを担当する**．

## 工程

| # | 工程 | skill | 使うエージェント |
| --- | --- | --- | --- |
| 1 | 配信ネタのリサーチ | `podcast-research` | `podcast-researcher` ×3 |
| 2 | 台本の執筆 | `podcast-script` | — |
| 3 | ファクトチェック | `podcast-factcheck` | `podcast-fact-checker` ×1（最大 5 件で打ち切り） |
| 4 | 構成レビュー | `podcast-review` | `podcast-marketer` |
| 5 | タイトル・概要欄 | `podcast-meta` | — |
| 6 | 配信管理表の更新 | `podcast-publish-log` | — |

共通の参照元は `src/PODCASTS/WEB小噺/SHOW_RULES.md`．

## 進め方

### 開始地点を決める

ユーザーの依頼から，どの工程から始めるか判断する．

- ネタが未定 → 1 から
- ネタは決まっている → 2 から
- 台本がある（既存ファイル or ユーザーが持参） → 3 から

**全工程を一気に流さない．** 各工程の終わりで成果物を見せ，次に進む前に承認を取る．
台本は書き直しのコストが高く，前工程の合意なしに進めると後で全部やり直しになる．

### 3 → 4 は並列で回せる

ファクトチェック（`podcast-fact-checker`）と構成レビュー（`podcast-marketer`）は
互いに独立しているので，**同じ応答内で両方 spawn してよい**．
結果が返ったら，事実の修正を先に当ててから構成の修正を当てる
（構成を先にいじると，事実修正の該当箇所がずれる）．

### 完了条件

- [ ] 台本が `src/PODCASTS/WEB小噺/Season5/<slug>.md` にある
- [ ] `📎` 参考リンクが本題直後に揃っている
- [ ] ファクトチェックの「要修正」が 0 件
- [ ] 本編の文字数が想定尺に収まっている
- [ ] `## 📣 配信メタ` にタイトルと概要欄がある
- [ ] `## 🎙️ 収録メモ` が埋まっている
- [ ] `src/SUMMARY.md` に 1 行追加した
- [ ] 配信管理スプレッドシートに行がある

最後に `pnpm build` の実行要否をユーザーに確認する
（`src/` → `docs/` を作り直すため，差分が大きくなる）．

## 中断と再開

工程の途中で中断された場合，台本ファイルの状態から進捗を判断できる．

- ファイルが無い → 工程 2 未着手
- `📚 参考情報` が無い → 工程 3 未実施
- `📣 配信メタ` が無い → 工程 5 未実施
- 冒頭の配信ステータスが「未配信」 → 工程 6 未実施
