### 本題

- 【つかみ】CSSのC、Cascading（カスケーディング）。英語には waterfall（滝）というシンプルな単語があるのに、なぜわざわざ cascade という言葉を選んだのか、という話
- 【背景/歴史】1994年、CERNにいた Håkon Wium Lie（ホーコン・ヴィウム・リー）が「Cascading HTML Style Sheets」という提案書を発表。当時はブラウザごとに見た目の指定方法がバラバラになりそうな、いわば群雄割拠の時代だった
- 【背景/歴史】同じ頃、Bert Bos（バート・ボス）も別のブラウザ向けに独自のスタイルシート案を考えていた。二人が連絡を取り合ってアイデアを統合し、その中で Lie 側の「カスケード」という概念だけが生き残って合体案の名前になった
- 【メインの小噺・裏話】cascade という単語はイタリア語の cascata（滝）、動詞 cascare（落ちる）、さらに遡るとラテン語の cadere（落ちる）が語源。「水が落ちる」がベースの言葉
- 【メインの小噺・裏話】ポイントは、cascade は一段でドーンと落ちる大きな滝ではなく、階段状に連続していくつも小さく流れ落ちる滝を指す言葉だということ。ブラウザ標準のスタイル → ユーザーが設定したスタイル → 制作者が書いたスタイル、という複数の発生源からのルールが、優先度の重みをつけながら段々に流れ込んで最終的な見た目に着地する、という仕組みにぴったりの比喩として選ばれた
- 【意外な事実や補足】ソフトウェア開発の世界には、CSSの提案より前から「ウォーターフォールモデル」という言葉がすでに存在していた。もしCSSも waterfall と名付けていたら、エンジニアの間で紛らわしいことになっていたかもしれない
- 【意外な事実や補足】Lie と Bos が実際に初めて顔を合わせたのは提案から半年ほど経った1995年4月のWWW会議で、それまでは離れた場所からのやり取りだけで仕様を練り上げていた。1996年に最初の正式勧告 CSS1 として世に出ることになる
- 【まとめ・締めのひとこと】普段何気なく使っている「カスケード」という言葉の裏には、水が階段状にじわじわ流れ落ちていくように、複数の場所からのスタイルが優先順位を持って重なり合っていく、というイメージがちゃんと込められていた、という小噺でした
