### 本題

今回は「第 8 回 Tech LT Podcast カレンダー」への参加回です．1 エピソード 5 分までというルールなので，いつもより短く，さくっといきます．

僕は数年前から，クリエイティブコーディング，ジェネラティブアートと呼ばれる分野で遊んでいます．プログラムを書いて，絵やアニメーションを描く趣味ですね．使っているのは p5.js という JavaScript のライブラリです．作品は OpenProcessing というサイトに置いているので，よかったら概要欄から覗いてみてください．

始めたきっかけは単純です．数学，特にアルゴリズムが好きで，プログラミングが好きで，抽象的なアートも好きだった．この 3 つを掛け算できる場所を探していたら，ジェネラティブアートに行き着きました．

ところが最近は，仕事でも趣味でも，Claude Code のようなコーディングエージェントにコードを書かせるのが当たり前になりました．自分の手でコードを書くことは，ほぼなくなっています．旅先で時間が空いたときでさえ，スマホの Claude アプリからリモートで指示を出しているくらいです．

じゃあ，クリエイティブコーディングも全部エージェントに任せるのか．僕も実際に，プロンプトだけで作品を作らせてみました．結果は，満足いくところまではいきませんでした．モデルの進化はすごくて，雑なプロンプトでもそれっぽい絵は出てきます．ただ，細部が違ったり，期待とまるで違う絵が返ってきたりする．僕のプロンプト力不足もありますし，描きたいものを言語化しきれていなかったのも大きいです．

それに，ただ絵が欲しいだけなら，そもそもコードは要らないんですよね．画像生成 AI に参考画像を 1 枚貼って，色合いはこう，輪郭はこう，と細かく伝えれば，絵は出てきます．

じゃあ僕は絵が描きたいのか．そう考えると，ちょっと違いました．絵は描きたい．でも，やりたかったのはアルゴリズムとアートを掛け合わせることです．

ジェネラティブアートには，必ずランダムな要素が入ります．実行するたびに違う絵が生まれる．これを毎回プロンプトで AI に頼むより，プログラムの中でやるほうが絶対にいいと思います．

もう 1 つは，後に残るものの違いです．コードがあれば，誰かがそれを改造して，また別の作品が生まれるかもしれない．プロンプトを共有したいなら，コードの中にコメントとして残しておけばいい．両方を渡せるほうが，後に残すものとしては強いと思います．

そして何より，僕はプログラミングで何かが形になっていく楽しさを，知ってしまいました．

なので今は，こう使い分けています．定番の描画処理は，手元のスニペットからコピペ．単純作業や，ただ書くだけの部分はエージェントに任せる．そして表現の部分は，コードを書く前にエージェントと対話して，ああでもない，こうでもないと詰めてから，最後にコードに落とし込む．自分でキーボードを叩かなくても，LLM という頭脳を借りてプログラミングしながら絵を描くのは，やってみると，だんだん楽しくなってきました．

### エンディング

コーディングエージェントが来て，人間がキーボードを叩く場面はたしかに減りました．早く絵が見たいので，僕もそうしています．

でも，エージェントと対話しながら少しずつ形にしていくのも，立派なプログラミングで，立派な創作です．トークンはだいぶ食いますけどね．

AI が入っても，クリエイティブの本質は変わらない．僕はそう感じています．
